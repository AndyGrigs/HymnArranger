## 📖 Опис проєкту

**HymnArranger** приймає одноголосну мелодію (MusicXML) і генерує повне дворучне баянне аранжування — фігуровану мелодичну лінію в правій руці та басовий супровід Stradella в лівій — за допомогою **детермінованого, правилового рушія** на базі [music21](https://web.mit.edu/music21/), а не непрозорої нейромережевої моделі.

Робочим корпусом проєкту є репертуар християнських гімнів, а музичні правила спираються на власний досвід автора як баяніста й аранжувальника. При цьому сам рушій розрахований на будь-якого музиканта чи аранжувальника, що працює з мелодичним матеріалом — баян є першим реалізованим інструментальним стилем.

Окремо була побудована та оцінена повноцінно навчена нейромережа — як **дослідницький бейзлайн**, що обґрунтовує вибір правилового підходу (див. [ML-бейзлайн](#-ml-бейзлайн-дослідницька-гілка) нижче). Вона не є частиною продукту, що постачається.

## ✨ Можливості

- 🎼 Приймає одноголосну мелодію у MusicXML (`.xml`, `.musicxml`, `.mxl`)
- 🪗 Детермінований правиловий рушій аранжування — без інференсу моделі
- 🎹 Понад десяток текстурних пресетів, окремі набори для простих (2/4, 3/4, 4/4) і складних (6/8, 9/8, 12/8) розмірів
- 🎻 Ліва рука Stradella з оптимізацією voice leading
- 🧩 Режим сюїти: тема + послідовність варіацій, відтворювана через random seed
- 📚 Режим "усі пресети": всі текстури підряд в одній партитурі — для порівняння
- 👁️ Перегляд нот у браузері (OpenSheetMusicDisplay) та відтворення MIDI (програма GM Accordion)
- ✍️ Набір мелодії прямо в браузері через вбудований редактор Flat.io, або завантаження файлу
- 🎵 **ABC-нотаційний редактор** — набір нот кнопками (тривалість, октава, акциденції), конструктор акордів і живий прев'ю нотного запису; підтримує `.abc`-формат без зовнішніх залежностей → [детальна інструкція](docs/abc-editor.md)
- 📄 Завантаження результату у форматах MusicXML, .mxl (стиснений) та MIDI
- 🧪 Задокументований нейромережевий бейзлайн для методологічного порівняння (див. нижче)

## 🚀 Швидкий старт

### Backend + CLI

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# CLI
python arranger.py melody.musicxml -p mixed -o out.musicxml   # один пресет
python arranger.py --all                                       # усі пресети, окремі файли
python arranger.py --merge                                     # усі пресети в одній партитурі
python arranger.py --suite --seed 42                            # тема + варіації

# HTTP API
uvicorn hymnarranger.api:app --reload
# → http://127.0.0.1:8000/docs
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

## 🧠 ML-бейзлайн (дослідницька гілка)

Паралельно з правиловим рушієм було реалізовано та навчено **encoder-decoder Music Transformer з Relative Position Representation (RPR)** (REMI-подібна токенізація з кастомними токенами `Voice_Melody` / `Voice_Bass` / `Voice_Chord`), навчений протягом 200 епох на Google Colab (T4 GPU), з точністю токенів ~81% та validation loss ~1.39.

Ця модель **не використовується у продукті**. Вона задокументована як перевірена точка порівняння: cross-entropy loss усереднює по багатьох валідних аранжуваннях, які допускає одна мелодія, що структурно погано підходить для цієї задачі "один-до-багатьох" — цей висновок і обґрунтував остаточний вибір на користь детермінованого правилового підходу. Код тренування та чекпоінти живуть поза цим репозиторієм (у Colab-ноутбуках); тут наявні лише скрипти підготовки датасету, спільні для обох гілок.
